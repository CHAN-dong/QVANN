# 大规模耗时估算（2026-10-14）

CPU：Intel Core i9-12900，16 核 / 24 线程。当前复现脚本固定
OMP_NUM_THREADS=1、OPENBLAS_NUM_THREADS=1。以下假定数据已在本地、
物理内存足够且不发生 swap；100M 是条件估计，本机当前内存不能完成完整实验。

实测 SIFT100K，128 维，M=16，efConstruction=100，100 queries：

| 项目 | 耗时 |
|---|---:|
| e_budget_relaxed_hnsw 全部 12 组参数 | 4.099 s |
| expansion_centric_merkle 三种方案 | 13.329 s |
| refinement_merkle_ordering 三种排序 | 5.845 s |
| 三个程序顺序运行总和 | 23.273 s |
| HNSW 新建图（独立基准，无缓存、不写磁盘） | 12.9678 s |

实验计时包含读取数据/索引、重新计算 ground truth、创建量化编码和 Merkle 树、
100 queries、写 CSV；不含编译、数据下载。新建图耗时只计 add/建图，
不含读数据及写 index 文件。全部运行成功；没有在 10M/100M 实测。

若简单乘 100/1000，三个实验在 10M 为约 38.8 分钟、100M 为约 6.46 小时。
这只是线性外推基线，不能作为保证或严格下界。

规划范围（当前完整三组、单线程实现）：

| 场景 | 10M | 100M |
|---|---:|---:|
| 已有对应 HNSW 索引，跑三组核心实验 | 约 40–90 分钟 | 约 6–18 小时 |
| 首次构建 HNSW 额外预算 | 约 0.5–2 小时 | 约 6–24 小时 |
| 首次构建并跑完整实验，取整后的总预算 | 约 1–4 小时 | 约 12–48 小时 |

范围是小规模实测和源码结构支持的粗略预算，而不是置信区间；
数据分布、图插入难度、内存带宽、磁盘、2 的幂 padding、排序开销等可能
让实际耗时超出此范围。100M 若换机器，CPU 性能也会改变结果。

主要扩展瓶颈：ground_truth 每个程序重复对所有向量做精确距离计算；
run_e 按 N 初始化并扫描 bitmap/距离数组；Merkle prove/verify 按整层扫描；
SQ4-code 进行全 N 排序。由此固定 E=64 不代表整体查询与 N 无关。

HNSW 构建可尝试 OpenMP 并行，但当前实验树构建和 GT 等代码主要是串行，
不能把总时间直接除以 24。也不能把 100K 输出中的 1–3 ms/query
直接当作大规模完整实验的查询耗时。
