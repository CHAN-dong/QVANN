# Residual PQ 与渐进式量化消融

配置：SIFT1M、IVF100、前 50 条 query、top-k=100、20k residual 训练样本、10 次 k-means。所有误差均为逐对象真实重构误差的保守上界。

为了直接测试“更小证书”的潜力，本实验采用紧凑 4-bit sub-code：128 维拆为 16 个 8 维子空间，每个子空间 16 个中心，打包后每层 8 bytes。

- `RPQ8`：单层 8-byte residual PQ，所有对象返回 code + 4-byte epsilon；
- `RPQ16`：两层 additive residual PQ，所有对象直接返回 16-byte refined code + 4-byte epsilon；
- `Progressive8to16`：先返回 8-byte code + epsilon；仅第一层失败对象再返回 8-byte refinement + 第二层 epsilon；仍失败才返回原向量。

## 判断

1. 这版紧凑 RPQ **无效于中低 nprobe**：8-byte code 的 128 维总重构误差太大，`LB=||q-x_hat||-epsilon` 很难超过较宽松的 tau；大量对象仍需返回 512-byte 原向量。
2. 第二层 refinement 有效，显著降低 exact-open，但仍不及 64-byte SQ4 的紧误差；例如 nprobe=8 时 RPQ16 只减少 35.48%，SQ4 减少 85.41%。
3. 渐进式机制本身只在第一层过滤率足够高时有效：nprobe=64/100 分别比固定 RPQ16 多减少 0.57/0.96 个百分点；中低 nprobe 因多数对象都要第二层，还多付第一层 epsilon，略差于固定 RPQ16。
4. nprobe=100 时 Progressive 达到 86.48%，已经接近但仍未超过 SQ4 的 86.60%。因此当前配置不能证明 RPQ 能进一步降低 VO，只证明渐进传输在 coarse bound 足够有效时有小幅收益。

该负结果不等价于所有 PQ 都无效。这里测试的是为极小 code 设计的 `M=16, K=16` 4-bit sub-code；标准 `M=16, K=256` 的 16-byte PQ 会有更小误差，但训练与编码成本更高。下一步若继续，应测试标准 8-bit sub-code、OPQ rotation，或在 16–32 byte 区间寻找误差/证书大小平衡点，而不能仅依赖更粗的 code。

payload 口径与 SQ 实验一致，不含 ID、hash、Merkle multiproof；完整数据见 `residual_pq_results_at100.csv`。
