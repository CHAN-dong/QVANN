# work9：可运行 V3DB 默认配置与低召回率实测

2026-10-20 用户授权：默认采用可运行 V3DB 的 Recall@10；所有方法扩充低召回率曲线；V3DB 超资源预算的高召回点不测、不预测；新实测回填外层 work9.xlsx。

四个默认目标：SIFT1M 70.5%、NYTimes-256 58%、DEEP1M 约78%；GloVe-100 暂用 M100/K1024/probe2 的搜索校准40.5%，必须完成真实证明后报告其实际召回。不同方法离散参数可能超过目标，主表及曲线始终保留实际召回，不能声称完全等召回。

所有查询采用IDs100..119，共20条，3次重复；搜索与出证单线程。保留原方法优化。只有完整60次且验证通过的测量才能进入表格；不对缺失点插值或外推。原先完整、相同协议的V3DB实测可以复用，未完成记录在新目录复制后断点续跑，旧证据不修改。

召回率曲线扩充到20–99%的20个目标档位。参数离散，不同目标可以共享同一个实际配置；图表横轴是实际Recall@10。V3DB保持默认PQ索引，逐整数probe测试，遇50GiB地址空间限制、构建关系预算或2^20证明域预算后停止。预算跳过、静态构建失败、真实出证失败分别说明，不解释成硬件绝对上限。

原始文件备份：`work9_before_resource_matched.xlsx`。每个结果先写入`records/`，再生成`work9_measured.xlsx`，核验能读回后覆盖外层原文件。检测到用户同时改表时停止覆盖，保留完成版供合并。旧辅助预测表保留为历史证据；四个主表只由本轮“资源匹配”来源更新。

运行命令（在内层项目目录）：

```powershell
.\scripts\run_work9_resource_matched_windows.ps1 start
```

`start`启动独立后台进程，拒绝重复启动；退出后可再次start，从已验证检查点继续。不要同时启动旧版填表器或旧版预测器，它们可能覆盖本轮表格。

进度：`runner.log`、`events.jsonl`、`progress.json`、`records/`；失败见`runner_failure.json`。只有`RUN_FINISHED.json`表示计划已执行完毕（仍可能有明确资源限制点）。V3DB每个大档位60次可耗数小时，全部K和规模扫描可能持续多天，不能把启动或部分回填称为全部完成。

核验：`scripts/audit_work9_resource_matched.py`直接重新读取CSV、核对60个样本、计时均值、召回率、VO字节数、负向测试和工作簿对应位置。`independent-validation.json`只证明当前已完成部分，不表示队列已完成。
