# work9：新增 V3DB baseline

用户范围：在原工作簿四个数据集的各比较面板新增 V3DB，实际测试后写回原文件。后续用户明确允许调整 PQ 配置尽量达到召回目标，并选择四个数据集统一 20 条查询 × 3 次重复。

## 数据和指标

- 四个主数据集：SIFT1M、GIST1M、GloVe-100、DEEP1M。复用原表准备的基库与 query IDs 100..119。
- SIFT 规模实验使用 BIGANN/SIFT1B 同源 100K/500K/1M/5M/10M 前缀；DEEP 使用官方同源前缀。GIST/GloVe 没有 5M/10M 基库，对应新增行标为不适用。
- 使用原表的 top-k 集合重合率，真值在原始预处理向量和对应 N 上重新精确计算；不沿用作者“真 top-1 是否出现在返回 top-k”定义。
- 原始基库不做新归一化；GloVe 继续使用原项目已准备的单位向量，L2 排序代表 cosine 排序。

## 实现

原作者仓库在 `V3DB-26VLDB/upstream`，固定 commit `a82ac732828591bd49b83d8f31c56fa4bd1cd9b2`。用于本轮的独立工作副本为 `V3DB-26VLDB/work9-author`；`work9-adapter.patch` 增加真实压缩证明导出、解码验证及原哈希函数的 Python 绑定，并优化电路外witness整理，不改电路约束或搜索算法。

作者 `convert_ft_set_i64` 在每个不同的f值上全表线性查找首次匹配的t位置，存在O(n²)宿主端开销。高精度配置已实际遇到该瓶颈。本轮用 `HashMap<value,BTreeSet<position>>` 维护首次匹配位置并执行同样的交换，保留原压缩、排序、padding和最终f/t序列。256组包含重复值和压缩碰撞的用例与原函数逐项一致，原basic门数仍21,198，真实证明及篡改检查通过。正式时间包含这个精确等价的宿主端实现，不冒充未优化作者wrapper的耗时。

训练采用作者 IVF-PQ / Faiss KMeans、容量约束重平衡、16-bit 仿射缩放和整数码本路径。为避免 GIST 临时三维距离张量过大，重平衡临时距离矩阵按行分块，并用浮点64位矩阵乘法计算整数平方距离。对输入整数和不超过 2^53 的中间范围做断言，小样本与作者原函数的迁移标签、迁移数量逐项比较通过。该适配在外层 Python 中完成，保留原函数源码。

基础 n_list：SIFT 1024、GIST 512、GloVe 1024、DEEP 1024；capacity 为不小于两倍平均列表长度的二次幂。K 初始256，PQ M 初始为8（GloVe为10以整除100维），随后测试子向量维数4/2/1对应的 M；必要时在最大 M 测 K=512/1024。所有尝试保留，按同一20查询工作负载选择达到99%的最小已测 M/K；若仍未达到，保留最好实测精度，并明确标记未达目标。调参不是留出评估。

## 测量

- 正式查询、证明和客户端验证单线程，逐任务顺序执行；训练可用16个 Faiss 线程，训练和正式测量不并发。
- 离线构建并固定快照根，正式查询不重新承诺整个数据库。
- Query ms 包含搜索、候选准备、witness、电路 build、prove、压缩和证明导出。扣除作者函数内部已经单独测量的验证时间。
- VO KB 为实际压缩证明序列化字节 / 1000，包括作者电路公开输入。验证密钥/电路数据预先可信，不当作每查询 VO；其指纹单独保存。
- Verify ms 包含实际压缩证明与电路数据的解码、证明验证以及 top-k / 查询 / 快照根的公开输入检查；不访问基库。
- 每项原始记录包含查询ID、repeat、实际Recall、各耗时、真实字节数、RSS、门数、证明hash。正式通过结果才能填数值；不会填估算值。

作者默认 `zero_knowledge=false` 和已有多重集挑战绑定问题未在本轮修订；表格应解释为作者原型的功能/性能复现，不是安全审计完成的实现。

## 资源边界

本机 WSL 约62 GiB RAM。完整 SIFT1M 原配置的预检样例（254,433门）实际生成了压缩证明，独立解码验证并检查公开输入成功，采样进程RSS约9 GiB。该样例与训练并发，因此其耗时完全排除在正式表格外。

正式任务在构造电路前检查候选/LUT关系padding后的元组数（上限2,000,000），可构造时检查真实gate-only门数（上限2,000,000，允许尝试至2^21域）。这在初始更保守预算基础上提高，以实际尝试更多可能在50 GiB内完成的配置。这些是本轮工作站预算，**超过预算不等于已经实测OOM，也不等于算法不可运行**。超出的任务会记录具体电路形状/门数并标记“超预算未测”，不捏造20×3次证明耗时。四个总体配置另外进行真实构建/证明尝试；正式子进程地址空间上限50 GiB，只有实际返回分配失败才记“内存不足(50GiB上限)”。若需更大机器，可调整预算后继续测量。

## 恢复运行（WSL）

```bash

/root/.venvs/v3db-work9/bin/python V3DB-26VLDB/scripts/work9_calibrate.py --dataset all
# PQ精度调优，保留全部尝试
/root/.venvs/v3db-work9/bin/python V3DB-26VLDB/scripts/work9_tune.py
# 全部面板正式任务；统一20×3；通过的样本与任务可恢复
/root/.venvs/v3db-work9/bin/python V3DB-26VLDB/scripts/work9_run_all.py --sampling 20x3
# 单独刷新表格
/root/.venvs/v3db-work9/bin/python V3DB-26VLDB/scripts/work9_fill.py
```
